Bivariate bicycle codes, by hand

Quantum LDPC codes are the leading route to low-overhead fault-tolerant quantum computers. Bivariate bicycle (BB) codes — like IBM's [[144,12,12]] “gross code,” the centerpiece of its 2029 roadmap — pack many logical qubits into few physical ones, but they're hard to picture because their checks reach across the chip.

A BB code is built from two polynomials A, B in x and y (cyclic shifts on an ℓ×m torus). The parity checks are HX=[A|B] and HZ=[Bᵀ|Aᵀ]; there are n=2ℓm data qubits and k=n−rank HX−rank HZ logical qubits. (The gross code uses 144 data qubits + 144 check ancillas = 288 physical qubits — not to be confused with the separate [[288,12,18]] code.)

  • Each qubit is touched by exactly 6 checks (3 X, 3 Z); each check measures 6 qubits.
  • An X error is caught by neighboring Z-checks; a Z error by X-checks (that's the syndrome).
  • In the paper's optimized bi-planar layout each check has four short-range + two long-range edges. This explorer instead lays qubits on the raw ℓ×m torus, so the edge toggle uses a simpler “a single step along one axis = local” rule — it won't reproduce the paper's exact 4+2 split (it's a visualization aid, not the paper's embedding).

Everything is computed live in your browser over GF(2). Nothing is sent anywhere.
